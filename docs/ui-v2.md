# 控制页面 V2

界面版本2.0.0，固件仍为conveyor-1.0.0；不需要重新烧录。

## 根据实际数据设计

当前N20空载短时起转已验证参数为1kHz、启动30%、上限30%，设备NVS已保存。主页面将请求占空比、限幅后的请求预览、设备实时回报三者区分。请求仍为0–100%，超过设备上限明确提示限幅，不伪装成更高实际输出。

方向按当前轴端视角约定为正转顺时针、反转逆时针；源码映射同一作用于指令、状态、目标和日志。20kHz/30%不能起转、1kHz/30%能起转的对照属于已有实物记录；新版页面重做不会把此前测试冒充新页面实转验收。

## 主要交互

连接设备→启用控制→选择转动方向。连接、重连、调参数均不自动启动。停止与急停保持独立，Esc可发软件急停，解除锁定后仍需再次启用。无效占空比不能发转动指令。

“填入实测配置”只修改本地表单，不立即写设备；停止且停用控制后保存，收到固件确认才显示成功。设备配置徽标只比较设备回报，不把未保存表单当设备状态。

连接方式会保存在本浏览器；USB直连会复用已授权的唯一匹配设备，否则仍显示浏览器选择器。没有自动连接或自动启用。Python本机串口服务仍可作为备用。

## 视觉与数据边界

暖白主面板、深色导航、墨绿主操作、红色急停；输出示意仅反映固件控制状态，不模拟传感器转速。没有RPM、电流、温度虚构数据。连接设置、设备参数和原始通信记录可展开。参数变更仍写ESP32 NVS；方向映射存项目hardware-profile.js。

页面提供窄屏适配；服务仅监听127.0.0.1，手机不能通过自己的127.0.0.1访问Mac。浏览器窄屏检查与手机真实USB/远程连接验收分别记录，不能混淆。

## 维护

以Git标签或Release版本保留页面和固件配套关系；网页修改不会自动更新设备固件或NVS。旧页面私有备份未纳入公开仓库。

## 本次验收结果

23项Node回归全部通过。Chrome新版页面通过Web Serial连接真实conveyor-1.0.0设备，读到1kHz/默认30%/上限30%，停止0%、未启用。验证了71%请求预览限制30%、空值/小数/101阻止启动、Esc实际急停ACK、解除后未启用、本地填表与设备参数分离、保存同一工作配置获得ACK。该阶段未发非零运行指令；后续实际运行验收见下段。

1665px桌面与Chrome iPhone16预设393×852的窄屏布局均无横向溢出。后者只证明浏览器模拟布局，不是实际iPhone串口或手机远程访问测试。已恢复桌面视口并关闭开发工具。

检查中发现两处静态内联样式被现有CSP拦截，已移入外部样式，不放宽安全策略；超限提示颜色类名亦已修正。刷新后未见新页面控制台错误。证据见verification/ui-v2-acceptance.json及三张ui-v2截图。

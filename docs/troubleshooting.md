# 故障排查与维护

## 没有串口

先确认 USB 数据线、连接器、实际供电；本次断电后设备消失属于预期。重新连接前隔离 VM。串口可能重编号，不能始终硬编码 usbmodemXXXX。枚举 303A:1001 只识别 Espressif 接口，不等于确定 ESP32-S3 或板型。刷写工具强制 ROM 芯片、Flash 容量与 USB 序列号匹配。

若无法进入下载模式，M5Stack 官方说明为按住复位按钮约两秒，内灯变绿后松开。复位或下载模式操作也必须在电机供电隔离后做。不要对其他串口尝试刷写。

## 串口忙／连接失败

关闭占用串口的旧面板连接、串口监视器或另一浏览器标签。本次发现旧项目 Python 服务仍运行在 8765；新项目使用 8766，不会自动关闭旧服务。新服务一次只允许一个控制客户端，Web Serial 和 relay 不能共用串口。旧 atoms3-panel 固件不是 JSON 协议，网页应拒绝握手，需核对后再刷写本版本。

## 电机不动

立即停止，不能长时间提高占空比。按次序核实：芯片型号与使能电平 → VM 实测电压和限流状态 → 公共地连续性 → AO1/AO2 端点 → 机械阻力 → 示波器观察 G5/G6、输出差分波形。软件回报 running 仅证明程序状态，不证明引脚波形或电机转动。

6V 电机在 5V 下和低 PWM 时可能起转不足；若不动，短脉冲结束后停止分析，不能把低占空比长期通电当作安全试验。独立限流源的设置与模块连续电流能力需匹配；不要做长时间人工堵转测试。

## 急停／通信超时

急停锁定需手动解除再使能；G41 按住时无法解除。超时、断线会撤销使能；重连不自动运行。若 UI 状态未知，不能据此确认电机停止，必要时使用硬件电源开关。

## NVS 与维护

版本 1.0.0 只保存设置，不保存方向/运行/使能。升级时先读当前参数、保存测试记录，构建并校验文件哈希，然后按 flash.py 备份整片 Flash。备份可能含之前固件的 Wi-Fi 凭证等隐私，只存本地，不纳入分享包。

修改 MotorCore.h 后跑 tools/test.sh；修改 LEDC、USB 或 NVS 后必须补对应实机验证。IDF/Arduino 版本迁移需检查 USB bool 语义、看门狗 API、LEDC 通道启停和分区；不能只看编译通过。当前固定 pioarduino 55.03.37 / Arduino 3.3.7，依赖版本与编译占用见 verification。

未来编码器只预留扩展方向；任何 RPM、电流、温度字段必须在加装传感器并校准后加入，禁止生成模拟值冒充实测。

## 测试环境限制

本机 AddressSanitizer 测试进程出现持续占用 CPU 的异常，已停止，仅采用正常原生执行与 UndefinedBehaviorSanitizer 完成安全状态机测试；没有把未完成的 ASan 标为通过。真实电机、USB、NVS 掉电测试仍不可由主机测试替代。
